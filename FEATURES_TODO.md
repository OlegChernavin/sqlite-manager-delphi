## Планируемые фичи

### 1. Корректная работа с BLOB при редактировании записей

- **Проблема сейчас**: при редактировании записи, если в одном из полей хранится BLOB, в гриде отображается строка вида `"BLOB (xxx bytes)"` или аналогичный маркер. При сохранении этот текст попадает обратно в SQL, и в базе вместо исходного бинарного содержимого оказывается просто текст `"BLOB"` (или маркер), что приводит к потере данных.
- **Что нужно сделать**:
  - При загрузке записи в `RowEditForm` не подменять реальные BLOB-данные строкой-маркером. Вместо этого:
    - либо хранить оригинальный `TBytes` по каждому BLOB-полю во внутренней структуре формы и не редактировать его как текст;
    - либо предоставить отдельный UI для работы с BLOB (кнопка «Просмотр/Изменить BLOB», диалог выбора файла и т.п.).
  - При сохранении формировать SQL так, чтобы:
    - текстовые/числовые/NULL-поля брались из редакторов;
    - BLOB-поля писались как параметризованные значения по сохранённому `TBytes`, а не по строке `"BLOB"`.
  - Предусмотреть поведение по умолчанию:
    - если пользователь BLOB не трогал — сохранять исходный BLOB без изменений;
    - если пользователь явно заменил BLOB — записывать новое бинарное содержимое.

### 2. Удобный просмотр содержимого BLOB-полей

- **Проблема сейчас**: BLOB отображаются как краткая строка (`"BLOB (xxx bytes)"`), нет удобного просмотра реального содержимого.
- **Что нужно сделать**:
  - При клике/двойном клике на ячейку с BLOB открыть отдельное окно/диалог «Просмотр BLOB»:
    - если данные детектируются как текст (валидный UTF-8/ANSI) — показывать их в многострочном редакторе;
    - если данные выглядят как бинарный файл известного формата — по возможности показывать предпросмотр или хотя бы базовую информацию (тип/сигнатура/размер).
  - Добавить контекстное меню:
    - «Сохранить BLOB в файл…»;
    - опционально «Копировать BLOB как hex/base64».
  - Гарантировать, что просмотрщик BLOB **не изменяет данные в БД**, пока пользователь не выполнит явное действие замены/импорта.

### 3. Сортировка по клику по названию колонки

- **Проблема сейчас**: в гриде результаты отображаются в текущем порядке, но нет стандартного поведения «клик по заголовку колонки = сортировка».
- **Что нужно сделать**:
  - Добавить обработчик клика по заголовкам `TStringGrid`:
    - минимум для `sgBrowse`;
    - опционально и для `sgExecute`.
  - Клик по колонке сортирует по ней; повторный клик меняет направление (ASC/DESC).
  - Сортировать с учетом типов колонок (используя `FColumnTypes`):
    - `sctInteger`, `sctReal` — числовое сравнение;
    - `sctText` — лексикографическое;
    - `sctNull` — единое правило размещения `NULL` (например, всегда в конец).
  - Если сортировка выполняется SQL-запросом, учесть `LIMIT/OFFSET`, применяя сортировку до пагинации и сохраняя текущие параметры сортировки для корректной навигации.
